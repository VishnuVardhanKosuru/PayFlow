1. System Overview
PayFlow consists of three user-facing layers and one backend layer: (1) iPhone capture through Shortcuts/Back Tap, (2) a mobile-first web application/PWA, (3) an iOS companion/widget layer for the Home Screen, and (4) Supabase for database, authentication and server-side API logic.
Core principle: the Shortcut captures minimal input; the backend remains the source of truth for transactions and computed financial metrics.

6. Natural-Language Parsing Without AI
The MVP can parse common patterns using deterministic rules before any LLM is introduced. Example input: “₹450 protein” → amount 450, description protein, category Protein. Example input: “250 uber blr trip” → amount 250, description uber blr trip, category Travel, trip Bangalore Trip if a matching active trip exists.
Normalize currency symbols and numeric formats such as 450, ₹450, 0.45k and 1.2k where safely supported.
Use user category names and synonyms to map text to categories.
Use merchant keyword mappings for common merchants.
Use active trip names to infer trip association.
When amount cannot be confidently parsed, return a validation error instead of creating a transaction.
7. Optional AI Integration Boundary
AI is an optional enhancement and must not be a hard dependency for core ledger functions. If an LLM is added later, the recommended architecture is to pass only the minimum required text and context to a server-side function. API keys must never be embedded in the mobile web app or iOS Shortcut.

12. Business Logic / Calculations
Metric
Calculation
Monthly Expense
SUM(transactions.amount) WHERE type=expense AND occurred_at in selected month
Monthly Income
SUM(monthly_income.amount) for selected month
Remaining
Monthly Income - Monthly Expense
Savings Rate
Remaining / Monthly Income × 100, when income > 0
Category Share
Category Expense / Monthly Expense × 100
Month-over-Month Change
(Current category spend - Previous category spend) / Previous category spend × 100, where prior spend > 0
13. Authentication & Security
Every database row containing financial data must be associated with a user_id.
Supabase Row Level Security (RLS) should restrict reads/writes to the authenticated user owner.
Service-role credentials must remain server-side and never be placed in the PWA, Shortcut or widget.
If an external AI provider is added, its API key must only be stored in server-side secrets.
Use HTTPS for all API access.
Do not log sensitive transaction payloads unnecessarily in production.
14. Error Handling
Scenario
System Response
Missing amount
Reject request with validation message; do not create transaction.
Invalid category
Use a controlled default only if configured; otherwise reject or ask user to select.
Unauthorized request
Return authentication/authorization error; do not expose transaction data.
Duplicate Shortcut request
Return the original transaction or safe duplicate response based on idempotency key.
Network unavailable
Shortcut shows failure; no false success message.
Widget data unavailable
Show cached/last-known safe summary rather than exposing partial calculations.
15. Performance Requirements
Normal transaction creation should complete within a few seconds over a healthy mobile connection.
Dashboard summary should be returned quickly enough for normal mobile use; aggregated queries should be indexed by user_id and date.
Use database indexes on user_id, occurred_at, type, category_id and trip_id as appropriate.
Widget payload should be small and optimized for glanceable rendering.

17. MVP Delivery Phases
Phase 1 — Supabase schema, authentication, transactions, categories and salary tracking.
Phase 2 — Mobile PWA dashboard and transaction management.
Phase 3 — iPhone Shortcuts + Back Tap quick capture and voice capture.
Phase 4 — Analytics/insights and optimized widget data endpoint.
Phase 5 — Native WidgetKit companion and deep linking.
Phase 6 — Optional AI enhancement after deterministic parsing proves insufficient.
18. Definition of Done
A user can sign in and see only their own data.
A monthly salary can be recorded and displayed on the dashboard.
An expense can be captured from the mobile web UI and an iPhone Shortcut.
Voice capture can create common expenses without a paid AI service.
Categories and optional trips can be created and attached to expenses.
Monthly totals and insights reconcile with the underlying transactions.
The Home Screen widget displays current financial status and deep-links into the product.
Core operations continue to function without an external LLM API.
